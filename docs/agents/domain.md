# 领域文档

本项目采用单一领域上下文：根目录 `CONTEXT.md` 保存领域术语，`docs/adr/` 保存架构决定。既有术语和 ADR 原位保留。

## 探索前阅读

- 阅读根目录 `CONTEXT.md`。
- 如将来出现 `CONTEXT-MAP.md`，按其索引阅读相关领域上下文。
- 阅读 `docs/adr/` 中与当前改动有关的 ADR。
- 某个文件不存在时继续工作，不要求预先创建空文档。术语或决定明确后再由 domain-modeling 按需创建。

## 使用统一术语

规格、任务、测试描述和设计讨论使用词汇表中的定义，不用词汇表明确排除的同义词。尤其区分真实识别与结果回放、展示区域与模型版面块/识别区域、原始模型输出与校对内容。

融合 docprase 时，尊重其对页面、LayoutBlock、Region、内容归属、阅读顺序和 DocumentIR 的区分。当前 App 的领域术语不替代源引擎的定义。

## ADR 冲突

拟议变更与现有 ADR 冲突时，先明确指出冲突和原因，再决定是否修改架构决定。不要悄悄绕过本地离线推理等既有决定。
