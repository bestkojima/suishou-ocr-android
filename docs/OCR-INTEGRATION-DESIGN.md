## 拟实施方案

### 输入与结果

首轮新增真实 OCR 入口只针对拍照和导入单张图片。保留现有 PDF、Office、JSON/ZIP 功能；它们的模型识别扩展不属于本轮。推理前统一处理图片 EXIF 方向，并在后台执行。

真实推理复用 docprase 的版面检测、区域规划、OvisOCR2 识别、DocumentIR 和资源导出。保留原始 DocumentIR/Markdown/图片资源，通过现有归一化层进入结果页、历史和导出。partial 区域保留状态及可用结果，不能表示为全页成功。

### 构建与模型

用 NDK 为 arm64-v8a 构建 docprase 与 MNN 视觉/LLM 后端，并建立 JNI 桥接。处理单库/分库链接识别问题，确保生产后端实际启用；不能只凭 native 库存在认定引擎可用。

沿用 App 内两个默认仓库下载模型，不把权重放入 APK。检查固定的 9 个必需工件、大小、SHA 和实际模型加载状态；自定义仓库仍保留下载能力，不自动承诺任何模型都可推理。模型根目录指向现有应用私有下载目录，临时文件指向可写缓存目录。首轮沿用现有 CPU 单线程配置。

### 作业与界面

新增原生作业控制层，与结果页生命周期分开管理；进度读取和取消不能被同步推理阻塞。一次只允许一个识别作业。拍照/导入保存输入后，模型就绪即自动启动；缺模型则保留输入并提供下载及稍后识别入口。

通过既有原生事件桥传送作业标识、阶段进度和终态，避免旧作业事件覆盖当前文档。结果页先展示真实识别进度；完成并落盘后，按已有展示逻辑回放结果。“暂停展示”只控制回放，“取消识别”单独控制作业。

返回首页后继续识别；失败或取消保留输入并支持重试。取消显示“取消中”，等原生安全停止和清理完成再进入终态。应用进程终止后不承诺从区域中间恢复推理，保留输入并允许重试。使用中的模型不能删除。重新识别另存新记录，旧结果和校对不被覆盖。

### 本轮验证与交付

1. 编译 arm64-v8a 普通/测试 APK，检查所打包 native 库及必需符号。
2. 使用本机同一引擎对样图执行一次新的真实识别，检查 JSON、Markdown、资源及 partial 状态，并核对 App 数据适配。
3. 验证模型缺失、真实作业事件驱动、失败/取消/重试、旧作业事件隔离、历史与校对保留，运行受影响的既有测试。
4. 提供可查看的 App 界面预览、APK、设计/领域文档和验证记录。
5. 记录设备端待验收项：模型加载、首图/重复推理、内存与耗时、EXIF、返回首页继续、取消、进程退出后重试、结果显示与导出。当前无设备，不宣称这些项通过。

本轮界面预览使用真实桌面推理得到的内容验证渲染；浏览器中的原生生命周期模拟应明确标注。桌面真实推理、浏览器验证和 Android 编译分别记录，不能合并为“APK 已成功推理”。

## 推理事实补充

- 本机 docprase 所需的版面与 Ovis 模型文件全部存在，合计约 576 MiB；当前后端要求固定工件 SHA。App 默认下载仓库的历史清单与这一要求相符，实际交付文件仍需核验。
- 当前后端限制 CPU 单线程；模型根目录和临时目录需要适配 Android 私有文件及缓存目录。
- C ABI 当前可提供真实阶段进度和作业结束后的完整内容，不能提供正文 token 或区域内容增量。边识别边显示正文需要扩展引擎接口。
- 取消请求按安全边界处理，可能等待当前区域生成结束；终态才表示执行及清理完成。
- 两个默认 ModelScope 仓库的本地历史清单覆盖全部 9 个必需工件，文件名与固定 SHA 均相符；实施时仍需检查实际远端及设备文件，不能把历史清单当作完整权重下载验证。
- 历史 Linux 单图记录约 84 秒、峰值 RSS 2.28 GiB；同引擎连续两作业约 94/87 秒、峰值 2.33 GiB，均存在 partial 区域。这是历史桌面记录，不是 Android 性能承诺，也不证明当前版本已完成验证。
