# 05: 交付 APK、真实识别预览及分项验收记录

**What to build:** 用户和维护者能够拿到普通/测试 arm64-v8a APK、以新的真实引擎输出呈现的 App 界面预览，以及覆盖完整工作流的验证记录；明确区分本机已验证能力和需要设备补齐的最终推理验收。

**Blocked by:** 03：贯通结构化结果、校对、排序和导出；04：贯通导航、取消和失败重试

**Status:** ready-for-agent

- [ ] 普通版和测试版 APK 可构建，检查架构、生产后端及所需原生符号，并确认没有打包权重。
- [ ] 记录一次新的同引擎真实识别的输入、模型/配置身份、终态、实际 JSON/Markdown/资源及可获得的耗时和内存，不复用历史报告代替新验证。
- [ ] 提供可查看的 App 界面预览和真实内容，验证文字、表格、公式、插图及 partial 提示；预览中的原生作业模拟明确标注。
- [ ] 集成验证模型缺失→下载准备→启动→结果保存展示，以及返回首页、冲突、取消后重试、重新识别、旧校对保留与导出组合场景。
- [ ] 运行受影响的既有浏览器和 JVM 检查，保留 PDF/Office/JSON/ZIP、下载、排序及编辑流程的相关回归结果。
- [ ] 交付记录分开列出 Android 编译、桌面真实推理、模拟桥接和浏览器渲染证据，不合并宣称 APK 内模型推理通过。
- [ ] 保留设备验收清单：实际加载、首图和重复推理、EXIF、内存/耗时、导航/取消/进程退出后重试、结果显示及导出；缺设备不阻塞本轮已约定的替代交付。
- [ ] 更新实现范围与已知限制的开发说明，保持本轮单图、离线、arm64 范围，不扩大到 PDF/Office OCR、token 流或服务器运行时后端。
