# 01: 打通输入保存、模型准备与本地引擎激活

**What to build:** 用户拍照或导入图片后，输入可靠保存；缺模型时进入待识别状态并可打开下载页。完整下载后应用校验支持的工件、激活本地生产引擎，并向用户显示实际加载成功或失败，形成从新输入到识别就绪的完整流程。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 拍照与单图导入先持久化原图，待识别输入可从历史重开，重启 App 后仍能找到。
- [ ] 缺模型、工件不匹配、文件齐备未加载、加载中、加载成功及加载失败在结果页与模型页一致呈现；缺模型时提供下载及稍后识别入口。
- [ ] 两个默认仓库配齐一个版面工件和八个 Ovis 工件，实际文件按存在性、预期大小和固定 SHA 核验；所选部分文件下载完成不等于识别就绪。
- [ ] 普通/测试 APK 提供 arm64-v8a 的 docprase 和 MNN 视觉/LLM 生产后端，正确处理合并库/分库链接，检查原生公共接口和后端启用证据。
- [ ] 模型使用现有私有下载目录，临时文件使用可写缓存；不复制第二份模型、不把权重放入 APK，沿用 CPU 单线程配置。
- [ ] 后台激活通过现有请求／事件桥连接界面，实际初始化成功后才进入就绪；缺文件、错误 SHA 或加载失败保留输入并给出可处理的提示。
- [ ] 识别准备状态与回放状态分开记录，旧文档仍可读取；自定义仓库下载保留，但不自动承诺推理适配。
- [ ] 复用公开桥接和存储测试验证输入保存、下载/校验、加载状态及历史重开，保留已有 PDF/Office/JSON/ZIP 行为。
- [ ] 当前环境交付原生打包检查、同引擎桌面加载证据及模拟桥接/UI 检查；设备实际加载明确列为待验收。
