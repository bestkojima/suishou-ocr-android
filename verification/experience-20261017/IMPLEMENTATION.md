## 实现结果

- JNI 引擎移入非导出的 `:ocr` 服务进程。新识别停止旧进程，仅保留最新请求，确认旧进程退出后启动新任务。主进程持有文档存储并提交结果，旧作业 ID 不能覆盖新请求。
- 正常完成后复用引擎；取消和切换清除句柄。主界面以 Android 原生容器执行 220ms 淡入/位移动画，无「正在切换识别」文字或确认框。
- 取消终态清除 stream、liveOutput 和未完成回放内容，隐藏继续输出。历史旧取消状态在读取时规范化，保留输入和已完成的文档。
- 结果页增加「反馈识别问题」：实际识别图片、逐字节原始 DocumentIR JSON、描述及可选分类。冻结反馈包、草稿保留、保存和系统分享已实现；自动提交支持可配置主/飞书备用服务及匹配回执校验。

## 兼容处理与边界

- Windows 下原有 `File.renameTo` 不覆盖已存在文件，导致多项 JVM 测试失败；改为已有图片保存路径同样使用的原子替换。Office 资源和 ZIP 条目统一为 `/`，测试断言使用平台路径分隔符。
- Windows SDK 35 的 AIDL 生成注释带有 `\userDebug`，触发 Java Unicode 转义错误；改为两个方法的显式 Binder 接口。大进度快照走同 UID 的私有缓存，避免 Binder 事务大小限制。
- 浏览器测试支持 `PYTHON`、`CHROMIUM_PATH`、`OCR_TEST_PORT`，本机使用端口 19484/19485 绕过系统保留端口。旧证据目录被测试改写的生成文件已恢复，本轮证据另存此目录。
- 导入自动识别和裁剪确认复用同一调度，但最终 APK 真机重点覆盖历史文档另存识别；没有将拍照/文件选择器的完整重复操作记为已测。
- GitHub/飞书接收服务尚未提供，未部署后端、未创建外部 Issue。当前 APK 明示未配置，可保存或系统分享；实际飞书收件及跨渠道去重仍需后续联调。接口见 [配置说明](../../docs/RECOGNITION-FEEDBACK.md)。设备未展示飞书分享目标，本轮只验证 Android 通用分享。

其他已记录问题（仓库存在性、后台轮询、样本重复、未下载删除按钮）本轮未修改。
