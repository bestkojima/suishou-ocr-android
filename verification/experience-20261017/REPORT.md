## 五项问题实测

### 1. 仓库存在性校验：已复现

1. 首页 → 设置 → 识别模型。
2. 添加 `experience-20261017-nonexistent/no-such-ocr-repo`。
3. 页面直接出现“自定义仓库 / 尚未下载”卡片，未提示仓库不存在。
4. 点击该卡片“浏览仓库文件”，才出现 `ModelScope HTTP 404`。

这是“添加无效远端仓库”场景的实测；没有删除用户的本地模型目录来模拟本地路径失效，也没有验证真实仓库远端后来被删除的场景。

证据：[添加成功但无校验](16-invalid-repo-added.png)、[浏览时才报 404](18-invalid-repo-browse.png)。测试入口已通过“移除入口”清理。

### 2. 后台 models 轮询关联的系统查杀：本轮未复现

第一轮从模型管理页退出到桌面，再打开系统设置并回到桌面，使 OCR 进入 cached 状态。退出前断开本轮 CDP 连接，避免主动读取页面造成持续唤醒。

- 约 18:34:07 退后台，18:35:59 返回，观察约 112 秒。
- 18:35:00.385 系统记录 `freezing 9605 cn.local.ocr`，同一时刻冻结 WebView 子进程 9644。
- 观察结束时 PID 仍为 9605，返回后原模型管理页正常恢复。
- `ApplicationExitInfo` 没有本轮新增退出；没有捕获 `excessive binder traffic during cached`。

“被冻结”和“被杀进程”必须分开；本轮只实测到前者。既有走查的查杀记录保留，不能依据这次未复现推翻历史反馈，也不能据此确定或否定轮询是根因。

证据：[系统冻结日志](background-observation-1.txt)、[观察前退出信息](background-exit-before.txt)、[观察后退出信息](background-exit-after.txt)。

第二轮从普通设置页退后台（18:37:25 至 18:39:25，约 120 秒）：系统在 18:38:34 冻结主进程 11406 和 WebView 11437；PID 未变化、没有新增系统查杀，重新进入后设置面板正常恢复。见 [第二轮日志](background-observation-2.txt)、[退出信息](background-exit-second.txt)、[恢复截图](24-settings-background-return.png)。两轮都未复现，不扩展为“长期后台稳定”的结论。

### 3. 样本回放历史重复堆积：已复现

首页打开“文字 / 表格 / 图片”后返回，重复两次。历史中的“中文 · 表格 · 四张插图”从 **7 条变为 9 条**，每次新增一条独立记录。

这些是 JSON 样本回放，不是模型识别。重复内容混入用户历史，后续找真实文档和清理记录的成本增加。

证据：[计数](sample-count.json)、[历史截图](14-duplicate-samples.png)。

### 4. 未下载时删除按钮可用：已复现“从未下载”场景

新建本轮测试仓库 `experience-20261017-nonexistent/delete-test`，卡片为“尚未下载”，“暂停”禁用，而“删除文件”仍启用。

点击后出现确认：“删除此仓库的下载文件和断点记录？”确认后执行完毕，卡片仍为“尚未下载”，删除按钮继续可用。只对没有文件的本轮测试仓库执行，未删除已下载的真实模型。临时入口随后移除。

“下载进行中/部分下载时能否删除”没有另行下载大文件测试；当前确认的是原走查中“从未下载”的情形。

证据：[确认框文字和执行后状态](undownloaded-delete-confirmation.json)、[截图](22-undownloaded-delete-completed.png)。

### 5. 旧识别任务阻塞新任务：3/3 复现

最小操作链：

1. 最近记录打开已完成的 `jc02.jpg`，点击“重新识别（另存）”，产生任务 A。
2. 等待页面显示真实模型识别阶段（不是 JSON 回放）。
3. 点击返回首页，打开另一份已完成文档 `jc06~4.jpg`，点击“重新识别（另存）”，尝试任务 B。
4. B 没有启动，原文档页显示：**“已有识别作业，请返回该文档或等待安全停止”**。
5. 返回 A，可以看到旧任务仍在生成；需要到旧文档点“取消识别”。

第一轮 A 从 0/14 继续到 1/14，返回时第二个区域已经输出 223 字符。点击取消后界面说明“当前区域完成及资源清理后结束”，随后仍出现 259 字符等增量。说明返回并没有取消旧作业，手动取消也不是瞬时结束。

第二轮以 `jc06~4.jpg` 的新识别为旧任务，返回 `jc02.jpg` 尝试重新识别，同样被拒绝。第三轮由独立脚本自动复现相同交互，断言新任务不应被阻塞，实际以 exit code 1 结束。

## 新发现：取消后的界面终态相互矛盾

已复现，建议单独跟踪为 BUG-013。

在 A/B 的取消测试中，上方已显示“已安全取消，输入已保留，可重试”，但同一页面仍出现：

- 阶段行：“正在识别区域”。
- 正文：“正在接收内容…”或“正在生成 · 28 字符”。
- 底部：“继续输出”。
- 计数上方回到“输入已保存 · 0/0 区域”，阶段行却保留 4/8 或 0/14。

这容易让用户误以为任务还没有停止，也会混淆“继续输出”与“重试识别”。等待一段时间提示仍在；退出文档再打开后，正文改为“等待真实识别结果”，但阶段行仍留着“正在识别区域”。

取消前已经显示的片段重开后不再展示，当前界面只承诺保留输入，本轮不将其直接判定为已保存数据丢失。需要讨论取消后是否保留部分结果以及如何明确展示。

证据：[取消后持续状态](20-cancel-state-after-minute.png)、[重开后状态](21-cancel-reopened.png)、[另一份文档取消后](13-cancel-complete.png)。

只读检查本轮第三份测试记录的持久化状态也显示 `recognition.state=cancelled`、`stage=region_started`、`liveOutput=true` 同时存在。该记录支持界面状态不一致的观察，不等于已经完成原因分析。精简状态快照见 [测试记录清单](test-records.json)。

## 讨论建议

1. 先确认“发起新识别就替换旧识别”的统一行为，覆盖文档重识别和新导入/拍照入口；本轮实际覆盖历史文档重新识别，不把其他入口算作已测。
2. 将取消、退出和完成后的文案/按钮/进度统一到可辨认的终态。
3. 仓库添加时给出明确校验结果，无下载内容时禁用或隐藏删除。
4. 样本回放是否复用固定体验记录、是否写入正式历史，留待产品讨论。
5. 后台问题保留待复现状态，需要捕获查杀当次系统日志后再确定原因。
