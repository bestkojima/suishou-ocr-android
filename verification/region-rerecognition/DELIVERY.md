# 校对区域重新识别交付记录

日期：2026-10-13。代码和本地 APK 已完成；未提交或发布新版本。

## 使用

打开已识别区域的“校对内容”，展开“重新识别此区域”，选择已下载的 Ovis 或 GLM，点击“开始区域识别”。默认优先选用另一个可用模型。可查看该区域原图、取消任务；关闭面板后可回到同一区域查看结果。

新结果先作为候选展示。点击“使用此结果校对”填入草稿，再点击“保存修改”应用。失败、取消和关闭不会自动覆盖旧内容，其他区域、已有校对和原始 DocumentIR 保留。识别仍有异常时保留待核对提示；持续重复由现有循环保护停止。

文字、表格和公式均复用保存的区域裁图及任务类型，不重新跑整页版面分析。没有裁图或不支持的区域明确说明原因；未下载模型不可选择。本次模型选择不修改设置中的默认模型。

## 实现边界

- Android 专用 `android_ocr_run_region` 通过现有同步作业入口维护作业、取消和结果释放；路由只在调用线程的本次识别期间有效。普通整页调用仍进入原流程，docprase 公共 ABI 不变。
- 单区域入口复用 `recognize_region`、终态判定和导出，保存真实尝试及停止原因。不调用版面模型，但沿用现有完整引擎的模型下载/加载契约。
- 全局只允许一个推理作业。切换模型时释放旧引擎，同模型复用；全局默认模型配置保持原值。
- 区域作业单独存入 `regionRecognition`，候选文件保存在文档的 `region-recognition/<jobId>/`。整页 `recognition` 状态与原始结果不会被区域任务覆盖。
- 前端按文档、区域、作业及序号处理返回；关闭后忽略迟到回调。进程中断的区域作业恢复为失败，不冒充已保存的整页成功。
- 同时保留异常发票表格恢复正文时的裁图引用，使这类表格也可重识别。

## 验证

- 两个变体各 82 项 JVM 测试通过，覆盖裁图路径、异常表格引用、单作业互斥、候选隔离、按次模型选择、旧引擎卸载、取消、失败、清理与中断恢复。
- `npm run test:web` 与 `node web/verify-live-recognition.mjs` 通过：选模型、候选不自动覆盖、采用后保存当前区域、其他校对保留、取消、迟到回复隔离、重开恢复、缺裁图和模型未下载提示；发票表格和原有整页实时显示回归通过。见 `ui.json`、`web-tests.txt` 及横竖屏截图。
- `app/src/test/cpp/region_recognition_test.cpp` 通过：文字/表格/公式任务、只导出一个区域、无版面调用、循环停止不重试、取消、重置失败和输出预算。见 `native-test.txt`。
- Ovis、GLM 真实模型均使用历史异常日期区域裁图，通过新增 `--region-type text` 直接识别，只有一个区域且 manifest 的 layout 为 `not_run`。Ovis 为 partial/repetition，生成 107 token 后停止；GLM 为 ok/normal，输出 27 token。均在同步调用返回前有流式正文，流式原文与保存的尝试一致。原文与运行记录位于 `ovis/`、`glm/`。
- 双变体构建与 lint 通过；APK 静态检查确认 arm64-v8a、C ABI/JNI/LLM、依赖闭合、原生 Release/-O3/NDEBUG、没有打包权重。见 `apk.json`、`build.json`。
