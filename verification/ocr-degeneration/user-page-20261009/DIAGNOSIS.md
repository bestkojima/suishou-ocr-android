# 用户扫描页：正文结束后异常续写

日期：2026-10-09。用户提供英文试卷原图并补充“最后会异常输出”。归入 BUG-002 的**重复生成／异常续写**；同属症状家族不等于根因相同。本次继续只诊断和记录，不实施修复。

## 实测事实

附件原图为 **6800×9067，61,655,600 像素**，不是聊天中 1368×1824 的预览。原图 SHA256 为 `0f69c46def894afc60ba0d36901578d9aa65705ad3a9510274e8915fb710f88e`，原样保存在 [source.png](source.png)。它是大尺寸、多段英文、可见背面透印的扫描页，不属于此前的低像素或大字少字合成样例。

使用已有固定真实模型、Linux 同源 Android backend、4 CPU 线程、Release、greedy、`use_mmap=false`／`kvcache_mmap=false`。整页运行一次，初次区域预算仍为生产的 512 token；处理完成，外层返回 0，原始流异常判定返回 1。总用时 175.56 秒仅供此次 Linux 运行记录，不代表 Titan_1 性能。

| 区域 | 实际源区域／视觉画布 | 原始生成中的异常 |
| --- | --- | --- |
| 第 9 题的前两行，reqr0009 | 4821×398／1952×160 | 先识别英文，`W: I did?` 后重复无依据的 `2023年1月1日`；512 token 内 48 次完整日期 |
| Part B 的 Directions，reqr0013 | 5033×784／1376×224 | 先识别完整说明，随后出现额外英文，再生成无正文的编号 `1.`、`2.`……`107.`，达到 token_limit |

## 隔离复现与判据

从整页实际传入模型的源区域提取图片，各自单独执行同一生产识别 backend：移除 UI、版面检测、前面的区域和历史。每个区域运行三次，为缩短诊断将上限设为 256 token，生产上限及重试未改。

| 单区域输入 | 明确判据，仅适用于此固定样图 | 结果 |
| --- | --- | --- |
| date-region | 可见 `W: I did?` 后，同一日期连续至少 6 次 | 3/3 异常续写，每次 23 个完整日期 |
| directions-region | 可见说明的最后一句结束后，至少 12 行连续递增的空编号 | 3/3 异常续写，每次完整生成编号至 45，尾部还有未完成的 46 |
| heading-region | 可见标题结束后，至少 32 个独立句点 | 3/3 异常续写 |

三个区域的三次直接调用与整页的**视觉 RGB 完全一致，实际 output_tokens 前缀也完全一致**。[逐项核对](isolation-equivalence.json)。说明异常在真实模型生成中已经出现，不需要前面区域的输出才能触发，不能用纯界面重复追加解释这些实例。区域隔离不是已经找到了最小的像素或字形阈值。

这些判据只用于人工查看过、没有对应日期/编号列表的固定区域，不能直接用于生产字符串截断。正常考试编号、表格行和合法重复尚未作为泛化负例验收。

已运行的快速复现命令：

```bash
python3 tools/debug/continuation_probe.py \
  --library /tmp/ocr-degeneracy-native/libdococr_c_diagnostic.so \
  --input verification/ocr-degeneration/user-page-20261009/captured/directions-region.crop.png \
  --output verification/ocr-degeneration/user-page-20261009/quick-number-rerun \
  --kind numbers --runs 1 --max-tokens 256
```

输出信号为 `ABNORMAL_CONTINUATION numbers`，退出 1。底层旧判据可能输出 `NO_REPEAT`／退出 0，含义仅为“没有持续的相同字符串”，不代表 OCR 正确；新 wrapper 针对此页空编号序列返回红。三个区域的全部命令、日志和三次结果见 [direct-commands.json](direct-commands.json)、[date](direct/date/continuation-verdicts.json)、[numbers](direct/numbers/continuation-verdicts.json)、[punctuation](direct/punctuation/continuation-verdicts.json)。

## 可能解释与后续区分方法

以下是待验证的候选，不是已确定原因。本次没有对这张用户图进行新的 penalty 或图像清理实验。

| 排序 | 可能解释 | 可证伪预测与限制 |
| --- | --- | --- |
| 1 | 透印、裁剪边缘或视觉表示影响末尾解释 | 同一区域保持尺寸、文字与采样不变，仅处理外围残留或背景，异常应改变。二值化会同时改变主文字和背景，不能凭一次改善单独证明是透印；图片观察本身也不能确定因果 |
| 2 | 模型在正确正文末尾继续选取续写 token，当前解码未及时结束 | 保持实际视觉像素和 prompt 不变，仅改变有效采样或结束策略，异常尾部应改变；必须同时检查正文是否正确和完整。此前合成图的 penalty 结果不能直接外推为这张图有效，更不能证明具体 EOS 机制是根因 |
| 3 | 区域间上下文或流式拼接引起尾部 | 若是必需条件，去除历史并单区域执行后应消失；实际三个区域均仍 3/3，且真实 token 前缀一致，因此这些条件无法充分解释当前实例 |

大尺寸原图、800 万像素尺寸对照均能触发，不能把本问题笼统定为“整图像素太低”。尚未证明它与此前大字/低像素循环具有相同内部原因。

## 已有保护与验收边界

最终 Markdown 在本次完整整页运行中将异常区域替换为校对提示/原图链接，没有保留日期和空编号列表。但原始流在 backend 返回前已经含有异常，最终过滤不能代替流式阶段的及时停止。标题区域提高 token 预算后继续输出 4096 token 的事实表明，单纯扩大上限对这一实例没有解决问题；未验证其他重试方式。
